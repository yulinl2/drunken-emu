# Hook mechanics (kind hook-rule, from S2) and repo observations (kind observation, from S9).
hook-rule.matcher-empty | hook-rule | VERIFIED | S2 | Matcher: empty, star or omitted | An empty matcher, a star, or no matcher matches everything, for every event that supports matchers. See [[term.matcher]].
hook-rule.matcher-exact-or-list | hook-rule | VERIFIED | S2 | Matcher: exact name or list | Letters, digits, underscores, hyphens, spaces, commas and pipes form an exact name or a list separated by pipes or commas.
hook-rule.matcher-regex | hook-rule | VERIFIED | S2 | Matcher: regex | Anything else is an unanchored JavaScript regex. For example, Edit.* matches NotebookEdit; use ^Edit$ for a whole-name match.
hook-rule.matcher-mcp-naming | hook-rule | VERIFIED | S2 | Matcher: MCP tool naming | MCP tools are named mcp__<server>__<tool>. The .* wildcard is required to match a whole server, as in mcp__memory__.*.
hook-rule.matcher-plugin-mcp-naming | hook-rule | VERIFIED | S2 | Matcher: plugin MCP tool naming | Plugin-bundled servers are named mcp__plugin_<plugin>_<server>__<tool>.
hook-rule.if-field | hook-rule | VERIFIED | S2 | Hook field: if | The if field takes one permission-rule expression, such as Bash(git *). It runs only on PreToolUse, PostToolUse, PostToolUseFailure, PermissionRequest and PermissionDenied. On other events the hook never runs.
hook-rule.levels | hook-rule | VERIFIED | S2 | Hook configuration levels | Hook configuration has three levels: the event, then a matcher group, then a handler list. Entries from every level merge rather than replace each other.
hook-rule.location-user-settings | hook-rule | VERIFIED | S2 | Hook location: user settings | Hooks in ~/.claude/settings.json apply to all projects on this machine. See [[setting-file.user]].
hook-rule.location-project-settings | hook-rule | VERIFIED | S2 | Hook location: project settings | Hooks in .claude/settings.json can be shared through version control. See [[setting-file.shared-project]].
hook-rule.location-local-settings | hook-rule | VERIFIED | S2 | Hook location: local settings | Hooks in .claude/settings.local.json apply to one project. Claude Code keeps the file out of git when it creates it. See [[setting-file.project-local]].
hook-rule.location-managed-policy | hook-rule | VERIFIED | S2 | Hook location: managed policy | Managed policy settings apply organization-wide and are controlled by an administrator. See [[setting-file.managed]].
hook-rule.location-plugin | hook-rule | VERIFIED | S2 | Hook location: plugin hooks file | A plugin's hooks/hooks.json applies while the plugin is enabled. See [[plugin.overview]].
hook-rule.location-skill-frontmatter | hook-rule | VERIFIED | S2 | Hook location: skill frontmatter | A hook in skill frontmatter is registered when the skill is invoked and stays for the rest of the session. See [[term.skill]].
hook-rule.location-subagent-frontmatter | hook-rule | VERIFIED | S2 | Hook location: subagent frontmatter | A hook in subagent frontmatter runs while that subagent runs, and Stop becomes SubagentStop there. See [[term.subagent]].
hook-rule.handler-command | hook-rule | VERIFIED | S2 | Handler type: command | Runs a shell command or an executable. Fields: command, args (exec form, no shell), shell (bash or powershell), async, asyncRewake, timeout, statusMessage, onFailure and if. On Windows, command must be a real .exe when args is set.
hook-rule.handler-http | hook-rule | VERIFIED | S2 | Handler type: http | POSTs the input JSON to url. Fields: url, headers and allowedEnvVars. A non-2xx response or a connection failure is a non-blocking error. Restricted by [[setting.kill-switch.allowed-http-hook-urls]].
hook-rule.handler-mcp-tool | hook-rule | VERIFIED | S2 | Handler type: mcp_tool | Calls an MCP tool. Fields: server, tool and input. Strings in input support ${path} substitution from the input JSON.
hook-rule.handler-prompt | hook-rule | VERIFIED | S2 | Handler type: prompt | Asks a model to evaluate the input. Fields: prompt (use $ARGUMENTS for the input JSON) and model. Default timeout 30 s.
hook-rule.handler-agent | hook-rule | VERIFIED | S2 | Handler type: agent | Experimental agent-based handler. Fields: prompt and model. Default timeout 60 s.
hook-rule.once | hook-rule | VERIFIED | S2 | Field: once | Skill frontmatter only. The hook is removed after its first successful run.
hook-rule.exit-0 | hook-rule | VERIFIED | S2 | Exit code 0 | Success. A single JSON object on stdout is parsed. Plain stdout is added to Claude's context only on UserPromptSubmit, UserPromptExpansion, SessionStart and PostModelSwitch. Stderr from an exit-0 hook never reaches Claude.
hook-rule.exit-2-blocks | hook-rule | VERIFIED | S2 | Exit code 2: blocking events | On events that can block, exit 2 blocks, and stderr is the reason unless the JSON supplies one. Events: PreToolUse, UserPromptSubmit, UserPromptExpansion, PreModelSwitch, PreCompact, Stop, SubagentStop, TeammateIdle, TaskCreated, TaskCompleted, ConfigChange (except policy settings), PostToolBatch, Elicitation, ElicitationResult, WorktreeCreate and WorktreeRemove.
hook-rule.exit-2-non-blocking | hook-rule | VERIFIED | S2 | Exit code 2: non-blocking events | On other events exit 2 does not block. On PostToolUse and PostToolUseFailure, stderr goes to Claude. On SessionStart, SubagentStart, SessionEnd, CwdChanged, FileChanged, PostCompact and PostModelSwitch, stderr goes to the user. Other events ignore it, including PermissionRequest, PermissionDenied and StopFailure.
hook-rule.exit-other | hook-rule | VERIFIED | S2 | Other non-zero exit codes | A non-blocking error. The action proceeds unless onFailure is block. The transcript shows the first line of stderr.
hook-rule.timeouts | hook-rule | VERIFIED | S2 | Hook timeouts | Command, http and mcp_tool hooks are cancelled at their timeout, and their output is dropped. On PreToolUse a timeout does not block. On PreModelSwitch a timeout does block.
hook-rule.timeout-defaults | hook-rule | VERIFIED | S2 | Default timeouts | Command, http and mcp_tool: 600 s. Prompt: 30 s. Agent: 60 s. On UserPromptSubmit, PreModelSwitch and PostModelSwitch, command, http and mcp_tool: 30 s. MessageDisplay: 10 s. SessionEnd shares a 1.5 s budget, raised to match a longer per-hook timeout of up to 60 s.
hook-rule.on-failure | hook-rule | VERIFIED | S2 | Field: onFailure | For command and http hooks (v2.1.295 or later). continue is the default. block acts like exit 2 on that event, and on PermissionRequest it denies. No effect on Stop, SubagentStop, TaskCompleted, TeammateIdle, or async hooks.
hook-rule.stdin-common-fields | hook-rule | VERIFIED | S2 | Stdin: common fields | Every command hook reads: session_id, prompt_id, transcript_path, cwd, scratchpad_dir (v2.1.257 or later), permission_mode, effort (with a level field), hook_event_name, agent_id and agent_type. HTTP hooks receive the same JSON as the POST body.
hook-rule.stdin-pre-tool-use | hook-rule | VERIFIED | S2 | Stdin: PreToolUse fields | PreToolUse adds tool_name, tool_input and tool_use_id. For Bash, tool_input holds command, description, timeout and run_in_background.
hook-rule.stdin-session-start | hook-rule | VERIFIED | S2 | Stdin: SessionStart fields | SessionStart adds source (startup, resume, clear, compact or fork), model (may be absent), agent_type (with --agent) and session_title (when set). On resume or fork after a prior response, it also adds seconds_since_last_response, context_tokens, prompt_cache_likely_expired and estimated_cache_write_usd.
hook-rule.stdin-stop | hook-rule | VERIFIED | S2 | Stdin: Stop and SubagentStop fields | Both add last_assistant_message, the final assistant text of the turn. Use it instead of reading the transcript.
hook-rule.stdin-model-switch | hook-rule | VERIFIED | S2 | Stdin: model switch fields | PreModelSwitch and PostModelSwitch add from_model and to_model.
hook-rule.stdin-notification | hook-rule | VERIFIED | S2 | Stdin: Notification fields | Notification adds message.
hook-rule.output-universal | hook-rule | VERIFIED | S2 | Output: universal fields | continue (default true; false stops Claude after the hook), stopReason, suppressOutput, systemMessage and terminalSequence. Some events discard them.
hook-rule.output-pre-tool-use | hook-rule | VERIFIED | S2 | Output: PreToolUse decision | hookSpecificOutput.permissionDecision (allow, deny, ask or defer), permissionDecisionReason and updatedInput, which replaces the tool arguments.
hook-rule.output-permission-request | hook-rule | VERIFIED | S2 | Output: PermissionRequest decision | hookSpecificOutput.decision.behavior (allow or deny), and decision.updatedInput.
hook-rule.output-session-start | hook-rule | VERIFIED | S2 | Output: SessionStart fields | hookSpecificOutput.additionalContext, initialUserMessage, sessionTitle, watchPaths and reloadSkills.
hook-rule.output-top-level-block | hook-rule | VERIFIED | S2 | Output: top-level block | A top-level decision of block is honored on UserPromptSubmit, UserPromptExpansion, PostToolUse, PostToolUseFailure, PostToolBatch, Stop, SubagentStop, ConfigChange and PreCompact. On TaskCreated it cancels the task.
hook-rule.output-size-cap | hook-rule | VERIFIED | S2 | Output size cap | additionalContext, systemMessage, initialUserMessage and plain stdout are each capped at 10,000 characters.
hook-rule.hook-specific-output-requires-event-name | hook-rule | VERIFIED | S2 | Output: hookSpecificOutput needs hookEventName | Every hookSpecificOutput object must name its event in hookEventName.
