# Processes (kind process), git and PR rules, injected-context types, environment classes, coverage gaps, session rules.
process.build | process | REPO | S9 | Build the node set | Edit build/src/*.txt, then run python3 docs/claude-code-pkm/build/build_nodes.py. The builder checks duplicate IDs, unknown kinds, statuses and sources, and dangling links. If any check fails, it writes nothing. Run it with --check to confirm that nodes/ and INDEX.md match the sources, without writing. Then regenerate docs/TREE.md with bin/gen_tree.py --write, and check it with --check.
process.background-time-limit | process | VERIFIED | S6 | Background time limit | Background Bash and PowerShell commands get 30 minutes by default, or the timeout passed with run_in_background, up to a 2-hour maximum. The limit applies only in unattended runs: -p, the SDK, CI and cloud sessions. A local terminal session has none. A command that moves to the background at its timeout gets 30 minutes from the move. Variables that raise the limits: [[env.bash-default-timeout-ms]] and [[env.bash-max-timeout-ms]].
process.bash-output-limits | process | VERIFIED | S6 | Bash output limits | A valid result is inline up to about 30,000 characters. Beyond that it is saved to a file, and a 2,000-character preview comes back. A failed result is inline up to about 10,000 characters, as a head-and-tail excerpt with no file path. Exit code 1 counts as valid only for grep, rg, egrep, fgrep, find, diff, test, [, git diff and git grep. Raise the inline ceiling with [[setting.bash-output-max-chars]].
process.monitor-deadline | process | VERIFIED | S6 | Monitor deadline | A watch has a deadline: 5 minutes by default, at most 30 minutes, and at most 10 minutes under -p. At the deadline the watch ends and Claude gets one notice. Cap question: [[question.q6]].
process.bash-cd-persistence | process | VERIFIED | S6 | Bash cd persistence | A cd in the main session carries to later Bash commands while it stays inside the project or an added directory. Subagent sessions never carry it. Outside those directories the working directory resets, and the result says so. [[env.claude-bash-maintain-project-working-dir]] turns the carry-over off.
process.bash-env-persistence | process | VERIFIED | S6 | Bash environment persistence | Variables set with export do not persist across Bash commands. Aliases and functions from the shell startup file are available. CLAUDE_ENV_FILE makes variables persist ([[env.claude-env-file]]).
process.foreground-to-background | process | VERIFIED | S6 | Foreground command moves to the background | A foreground command that reaches its timeout is moved to the background, not stopped, unless it starts with sleep. CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1, or bare mode, stops it instead ([[env.claude-code-disable-background-tasks]]).
process.background-stop-rules | process | VERIFIED | S6 | When a background command stops | A command started by a foreground subagent stops when that subagent's run ends. A command started by the main conversation, or by a background subagent, runs until it exits, is stopped, or reaches its limit. A -p run stays open until its command ends.
process.memory-cap | process | VERIFIED | S6 | Tool memory cap | On Linux and WSL, CLAUDE_CODE_TOOL_MEMORY_LIMIT caps the memory that Bash, PowerShell and Monitor commands share, using a memory cgroup. If the cgroup cannot be set up, commands run uncapped. Permission-gating hooks are excluded from the cap. See [[env.claude-code-tool-memory-limit]].
process.ask-user-question-timeout | process | VERIFIED | S6 | Question auto-continue | An unanswered AskUserQuestion can close after 60 seconds, 5 minutes or 10 minutes, and Claude continues on its own judgment. The timer never starts in background sessions, screen-reader mode or Remote Control. See [[setting.ask-user-question-timeout]].
process.loop-pacing | process | VERIFIED | S6 | Self-paced loop | A /loop can pace itself. At the end of each iteration Claude calls ScheduleWakeup for the next run, between 1 minute and 1 hour out. See [[tool.schedule-wakeup]].
process.session-cron-expiry | process | VERIFIED | S7 | Session cron expiry | Recurring session-scoped jobs expire after 7 days: they fire one last time, then are deleted. A recurring job can run up to half its period late, at most 30 minutes. See [[tool.cron-create]].
process.subagent-permission-routing | process | VERIFIED | S6 | Subagent permission routing | Launching a subagent does not prompt by itself; the subagent's own tool calls are checked against the permission rules. Foreground subagents show prompts in place. Background subagents send them to the main session, where Esc denies one call. See [[tool.agent]].
git-rule.designated-branch | git-rule | SESSION | S8 | Develop on the designated branch | Commit and push only to the designated branch, and create it locally if it does not exist.
git-rule.push-retry | git-rule | SESSION | S8 | Retry network failures with backoff | Retry network failures only, up to four times, with backoff of 2, 4, 8 and 16 seconds. Other failures are reported, not retried.
git-rule.open-pr-after-push | git-rule | SESSION | S8 | Open a ready PR after a push | After a push, open a ready-for-review pull request if none is open. A merged or closed PR does not count.
git-rule.template-check | git-rule | REPO | S9 | No PR template in this repo | .github/ holds only workflows/, and the root has no PULL_REQUEST_TEMPLATE. The PR body is therefore free-form.
git-rule.subscribe-pr | git-rule | SESSION | S8 | Subscribe after creating a PR | Subscribe to the PR's activity right after creating it, so CI and review events reach the session ([[tool.remote-subscribe-pr-activity]]).
git-rule.no-history-rewrite | git-rule | SESSION | S8 | Never rewrite history | Never rewrite another author's branch history. Never stack commits on a merged PR's history: start a fresh change from the default branch, and keep any unmerged commits.
git-rule.attribution | git-rule | SESSION | S8 | Attribution in commits and PRs | Commit trailers and PR footers follow the attribution reminder ([[injected.attribution-reminder]]). GitHub comments end with the attribution footer. The trailer decision is [[dec.d4]].
git-rule.no-model-identifiers | git-rule | SESSION | S8 | No model identifiers in pushed artifacts | Anything pushed to a repository carries no model identifiers. See [[dec.d5]].
git-rule.outputs-default | git-rule | SESSION | S8 | Human-facing outputs default to the outputs folder | The user's preference: sustained human-facing materials go to /mnt/user-data/outputs by default. This session's git rules designate the repo branch instead ([[question.q13]]).
git-rule.env-docs | git-rule | SESSION | S8 | Environment questions go to read_documentation | Questions about the container, connectors, network or sessions are answered by calling read_documentation first ([[tool.remote-read-documentation]]).
