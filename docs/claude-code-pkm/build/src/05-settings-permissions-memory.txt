# Settings files, precedence, settings behaviors, permission modes, permission rules, memory.
setting-file.user | setting-file | VERIFIED | S3 | Settings file: user (~/.claude/settings.json) | Applies to you in every project on this machine. Use for personal preferences and your own permission rules. Never shared. See [[precedence.user]].
setting-file.shared-project | setting-file | VERIFIED | S3 | Settings file: shared project (.claude/settings.json) | Applies to everyone working in the folder. In a git repository, commit it so teammates get the same settings. Use for team permissions, hooks, plugins and project environment variables.
setting-file.project-local | setting-file | VERIFIED | S3 | Settings file: project local (.claude/settings.local.json) | Applies to you, in this project only. Claude Code keeps it out of git when it creates the file. A hand-made file needs its own .gitignore entry.
setting-file.managed | setting-file | VERIFIED | S3 | Settings file: managed | managed-settings.json and other managed sources apply to everyone the organization deploys them to. Use for security policy and compliance. See [[precedence.managed]].
setting-file.global-config | setting-file | VERIFIED | S3 | Settings file: global config (~/.claude.json) | Holds the sign-in session, MCP server configurations, per-project state such as trust decisions, and the global config keys that /config writes. Claude Code writes it; you rarely edit it by hand.
precedence.managed | precedence | VERIFIED | S3 | Precedence level 1: managed | The highest level. Nothing in your own files or in --settings overrides a managed key. See [[setting-file.managed]].
precedence.command-line | precedence | VERIFIED | S3 | Precedence level 2: command line | JSON passed with --settings for one session. It overrides the same keys in project and user files; keys it omits keep their file values. See [[flag.settings]].
precedence.project-local | precedence | VERIFIED | S3 | Precedence level 3: project local | .claude/settings.local.json. See [[setting-file.project-local]].
precedence.shared-project | precedence | VERIFIED | S3 | Precedence level 4: shared project | .claude/settings.json. See [[setting-file.shared-project]].
precedence.user | precedence | VERIFIED | S3 | Precedence level 5: user | ~/.claude/settings.json, the lowest level. See [[setting-file.user]].
precedence.rule | precedence | VERIFIED | S3 | Precedence rule | A key set at a higher level overrides the same key below it. List keys are the exception: they merge (see [[precedence.lists-merge]]).
precedence.env-not-a-level | precedence | VERIFIED | S3 | Environment variables are not a level | Each variable and key pair has its own rule. For example, ANTHROPIC_MODEL in the shell applies over the model key from any file, while ANTHROPIC_DEFAULT_MODEL applies only when no file sets model. An env block inside a settings file is an ordinary key.
precedence.lists-merge | precedence | VERIFIED | S3 | List keys merge | List keys such as permissions.allow merge across files. Exceptions: fallbackModel takes the whole value from the highest file that defines it; modelPicker takes the whole value from managed, --settings or user settings and ignores project and local files (v2.1.242 or later); availableModels applies the managed list as-is; modelSettings resolves per model together with effortLevel.
precedence.managed-exceptions | precedence | VERIFIED | S3 | Managed exceptions | A few security-sensitive keys let a restrictive value from a lower scope win over a managed value. Example: [[setting.managed-exception.disable-claude-ai-connectors]].
setting.live-reload | setting | VERIFIED | S3 | Live reload of settings | Claude Code watches settings files and reloads them. Edits to permissions, hooks and apiKeyHelper apply to the running session without a restart. A settings file created mid-session loads if its folder existed at start; a .claude folder created in the same session also loads. Some keys are read only at start. The hook case conflicts with repo observations: [[question.q1]].
setting.broken-json-error | setting | VERIFIED | S3 | Broken file: Settings Error | A user, project or local file with invalid JSON or a rejected value triggers a Settings Error. At an interactive start, a dialog offers to fix the file with Claude's help, to exit, or to continue without the broken settings.
setting.broken-entry-warning | setting | VERIFIED | S3 | Broken entry: Settings Warning | Individual entries that fail, such as a malformed permission rule or an unknown hook event name, trigger a Settings Warning. Claude Code skips those values and keeps the rest of the file.
setting.managed-invalid-entries | setting | VERIFIED | S3 | Broken managed entries | Claude Code keeps enforcing the rest of a managed file, drops the invalid entries, and falls back to stricter values for the affected keys until they are fixed.
setting.print-mode-broken-file | setting | VERIFIED | S3 | Broken file in print mode | In -p runs no dialog appears. The broken file or value is skipped and the run continues. claude doctor shows what was dropped. See [[cli.doctor]].
setting.cloud-user-local-not-read | setting | VERIFIED | S3 | Cloud sessions: user and local files not read | ~/.claude/settings.json and .claude/settings.local.json are not read in a cloud session. The local file is not in the clone.
setting.cloud-repo-file-read | setting | VERIFIED | S3 | Cloud sessions: repo settings read | In a single-repository cloud session, the repo's .claude/settings.json is read, because the file is part of the clone. In multi-repository Anthropic-hosted sessions, only enabledPlugins and extraKnownMarketplaces are read from each repo's file.
setting.cloud-device-managed-not-read | setting | VERIFIED | S3 | Cloud sessions: device managed files not read | A managed-settings.json file or MDM profile on the device does not reach a cloud session. Server-managed settings do.
setting.schema-url | setting | VERIFIED | S3 | Settings $schema line | A $schema line points to the published JSON schema for Claude Code settings. It gives editor autocomplete and validation, and it can lag behind the newest CLI releases.
setting.permissions-default-mode-limit | setting | VERIFIED | S3 | permissions.defaultMode limit | The values auto and bypassPermissions do not take effect from project or local files. Before v2.1.257, bypassPermissions took effect from any file. See [[permission-mode.auto]] and [[permission-mode.bypass-permissions]].
setting.bash-output-max-chars | setting | VERIFIED | S6 | bashOutputMaxChars | Sets the inline ceiling and read-back window for Bash output, up to 128,000 characters (v2.1.261 or later). When set, Claude Code ignores BASH_MAX_OUTPUT_LENGTH. See [[env.bash-max-output-length]] and [[process.bash-output-limits]].
setting.ask-user-question-timeout | setting | VERIFIED | S6 | askUserQuestionTimeout | 60s, 5m or 10m auto-continues an unanswered AskUserQuestion. It can also be set from the /config row. Background sessions, screen-reader mode and Remote Control never start the timer. See [[tool.ask-user-question]].
setting.effort-level | setting | VERIFIED | S3 | effortLevel and modelSettings | effortLevel and modelSettings hold the default effort per model. /effort changes effort mid-session. See [[flag.effort]] and [[cmd.effort]].
setting.viewmode | setting | VERIFIED | S4 | viewMode | The display mode setting. --verbose overrides it for one session. See [[flag.verbose]].
setting.ax-screen-reader | setting | VERIFIED | S4 | axScreenReader | Screen-reader output setting. The --ax-screen-reader flag and the CLAUDE_AX_SCREEN_READER variable take precedence over it. See [[flag.ax-screen-reader]].
setting.managed-exception.disable-claude-ai-connectors | setting | VERIFIED | S3 | Managed exception: disableClaudeAiConnectors | disableClaudeAiConnectors: true from any scope is honored, even when a managed source sets false.
setting.managed-exception.enable-artifact | setting | VERIFIED | S3 | Managed exception: enableArtifact | enableArtifact: false, and disableArtifact: true, from any scope are honored even when a managed source sets true. Nothing turns the Artifact tool back on. Requires v2.1.242 or later.
setting.managed-exception.isolate-peer-machines | setting | VERIFIED | S3 | Managed exception: isolatePeerMachines | isolatePeerMachines: true from any scope is honored, even when a managed source sets false.
setting.managed-exception.block-reads-outside-working-directories | setting | VERIFIED | S3 | Managed exception: blockReadsOutsideWorkingDirectories | permissions.blockReadsOutsideWorkingDirectories: true from any scope is honored, even when a managed source sets false. Requires v2.1.257 or later.
setting.managed-exception.classify-all-shell | setting | VERIFIED | S3 | Managed exception: autoMode.classifyAllShell | autoMode.classifyAllShell: true from ~/.claude/settings.json or --settings is honored, even when a managed source sets false.
setting.managed-exception.remote-control-at-startup | setting | VERIFIED | S3 | Managed exception: remoteControlAtStartup | remoteControlAtStartup: false from project or local settings is honored, even when a managed source sets true. A true in project or local settings is ignored.
setting.managed-exception.cross-session-inbound | setting | VERIFIED | S3 | Managed exception: crossSessionInbound | A stricter value from project or local settings is honored over managed, --settings and user values. The ladder is accept, then hold, then refuse. A project or local value that is not stricter is ignored.
setting.managed-exception.use-auto-mode-during-plan | setting | VERIFIED | S3 | Managed exception: useAutoModeDuringPlan | false from any managed source, --settings, user or local settings is honored, even when the winning managed source sets true. A false in project settings is ignored.
setting.managed-exception.sync-claude-ai-skills | setting | VERIFIED | S3 | Managed exception: syncClaudeAiSkills | false from any managed source, --settings, user or local settings is honored. A false in project settings is ignored.
setting.managed-exception.sync-claude-ai-plugins | setting | VERIFIED | S3 | Managed exception: syncClaudeAiPlugins | false from any managed source, --settings, user or local settings is honored. A false in project settings is ignored.
setting.managed-exception.max-effort-level | setting | VERIFIED | S3 | Managed exception: maxEffortLevel | A lower cap from any scope, including --settings, is honored; the lowest cap applies. Requires v2.1.267 or later.
setting.kill-switch.disable-all-hooks | setting | VERIFIED | S2 | Kill switch: disableAllHooks | disableAllHooks: true turns off all hooks. It cannot disable managed hooks unless the setting is in managed settings. See [[term.hook]].
setting.kill-switch.allow-managed-hooks-only | setting | VERIFIED | S2 | Kill switch: allowManagedHooksOnly | allowManagedHooksOnly, in managed settings, blocks user, project, local and plugin hooks, except plugins force-enabled in managed enabledPlugins.
setting.kill-switch.allowed-http-hook-urls | setting | VERIFIED | S2 | Kill switch: allowedHttpHookUrls | allowedHttpHookUrls restricts which URLs HTTP hooks may call. See [[hook-rule.handler-http]].
setting.kill-switch.http-hook-allowed-env-vars | setting | VERIFIED | S2 | Kill switch: httpHookAllowedEnvVars | httpHookAllowedEnvVars restricts which variables may be interpolated into HTTP hook headers.
permission-mode.default | permission-mode | VERIFIED | S4, S7 | Permission mode: default | The standard mode name, and the starting mode unless a flag or setting says otherwise. Its UI label is Manual ([[permission-mode.manual]]). Behavior detail is on the permission-modes page, which was not fetched ([[gap.harness-pages-not-fetched]]). Flag: [[flag.permission-mode]].
permission-mode.accept-edits | permission-mode | VERIFIED | S4, S7 | Permission mode: acceptEdits | A mode name listed in the CLI reference and in the create_session enum. Behavior detail was not fetched.
permission-mode.plan | permission-mode | VERIFIED | S4, S6, S7 | Permission mode: plan | A mode name. Plan mode asks for approval of a plan ([[tool.exit-plan-mode]]). A remote session started in plan mode waits for a person to approve.
permission-mode.auto | permission-mode | VERIFIED | S4, S6 | Permission mode: auto | A mode name. A classifier decides most prompts. Auto mode is in the Shift+Tab cycle by default; start in it with --permission-mode auto. It also reviews Monitor commands and WebSocket opens ([[tool.monitor]]).
permission-mode.dont-ask | permission-mode | VERIFIED | S4, S7 | Permission mode: dontAsk | A mode name listed in the CLI reference and in the create_session enum. Behavior detail was not fetched.
permission-mode.bypass-permissions | permission-mode | VERIFIED | S4, S7 | Permission mode: bypassPermissions | Skips permission prompts. The flag --dangerously-skip-permissions equals it. --restricted refuses it. --allow-dangerously-skip-permissions adds it to the Shift+Tab cycle without starting in it.
permission-mode.manual | permission-mode | VERIFIED | S4 | Permission mode: manual (alias) | An alias for default, from v2.1.200. The UI labels default as Manual. claude --help lists manual in place of default; both values work.
permission-rule.form | permission-rule | VERIFIED | S3, S6 | Rule form: ToolName(specifier) | Rules take the form ToolName(specifier) in allow, ask and deny lists, and in the /permissions interface. Hook matchers use bare tool names instead ([[hook-rule.matcher-empty]]). See [[term.permission-rule]].
permission-rule.specifier-bash | permission-rule | VERIFIED | S6 | Specifier: Bash command patterns | Bash(npm run *) matches command patterns for Bash and Monitor. See [[tool.bash]] and [[tool.monitor]].
permission-rule.specifier-powershell | permission-rule | VERIFIED | S6 | Specifier: PowerShell command patterns | PowerShell(Get-ChildItem *) matches command patterns for the PowerShell tool. See [[tool.powershell]].
permission-rule.specifier-read-edit | permission-rule | VERIFIED | S6 | Specifier: path patterns | Read(~/secrets/**) matches paths for Read, Grep, Glob and LSP. Edit(/src/**) matches paths for Edit, Write and NotebookEdit. See [[tool.read]] and [[tool.edit]].
permission-rule.specifier-skill | permission-rule | VERIFIED | S6 | Specifier: skill names | Skill(deploy *) matches skill names. See [[tool.skill]].
permission-rule.specifier-agent | permission-rule | VERIFIED | S6 | Specifier: subagent types | Agent(Explore) matches subagent types. See [[tool.agent]].
permission-rule.specifier-webfetch | permission-rule | VERIFIED | S6 | Specifier: WebFetch domains | WebFetch(domain:example.com) matches a domain. See [[tool.web-fetch]].
permission-rule.specifier-websearch | permission-rule | VERIFIED | S6 | Specifier: none for WebSearch | WebSearch has no specifier. Allow or deny the tool as a whole. See [[tool.web-search]].
permission-rule.no-specifier-tools | permission-rule | VERIFIED | S6 | Tools with bare names only | Tools such as ExitPlanMode and ShareOnboardingGuide accept only the bare tool name, with no specifier.
permission-rule.edit-grants-read | permission-rule | VERIFIED | S6 | Edit allow grants read | An Edit allow rule also grants read access to the same path, so no matching Read rule is needed.
permission-rule.read-deny-blocks-edit | permission-rule | VERIFIED | S6 | Read deny blocks Edit and Write | A Read deny rule also blocks Edit and Write on the same path, including creating a new file there. For Write, this check requires v2.1.228 or later.
permission-rule.bash-deny-disables-powershell | permission-rule | VERIFIED | S6 | Bash deny also turns off PowerShell on Windows | On Windows with Git Bash installed, a Bash deny (scoped or bare, from settings or --disallowedTools) also turns the PowerShell tool off for the session. Keep it on with CLAUDE_CODE_USE_POWERSHELL_TOOL=1 or a scoped PowerShell rule. See [[env.claude-code-use-powershell-tool]].
permission-rule.allow-ask-deny-lists | permission-rule | VERIFIED | S3 | Allow, ask and deny lists | permissions.allow, permissions.ask and permissions.deny are the three rule lists. deny and ask apply right away; allow in project files waits for trust ([[permission-rule.project-trust]]).
permission-rule.project-trust | permission-rule | VERIFIED | S3 | Project trust for allow rules | Allow rules in project files (permissions.allow, permissions.additionalDirectories, extraKnownMarketplaces and most env values) apply only after each user trusts the folder. Until then the user still sees prompts.
permission-rule.saved-approval-local-file | permission-rule | VERIFIED | S3 | Saved approvals write to the local file | Choosing "Yes, and don't ask again" on a Bash prompt saves an allow rule to .claude/settings.local.json. The CLI writes only to the local file. The VS Code approval card can choose the shared file instead.
permission-rule.managed-allow-merge | permission-rule | VERIFIED | S3 | Organization allow rules still merge | Organization allow rules apply alongside your own. allowManagedPermissionRulesOnly stops the merge.
memory.claude-md | memory | INDEX | S1, S8 | CLAUDE.md | Persistent project instructions that load into context. The memory page covers the hierarchy, which was not fetched ([[gap.memory-page]]). This session shows the project CLAUDE.md as an injected reminder with its path ([[injected.claude-md-reminder]]).
memory.agents-md | memory | INDEX | S1 | AGENTS.md | A persistent-instructions file name accepted alongside CLAUDE.md, according to the memory page index description.
memory.auto-memory | memory | INDEX | S1, S4 | Auto memory | Claude keeps notes automatically across sessions, according to the memory page index. The auto-memory location is per-user context that [[flag.exclude-dynamic-system-prompt-sections]] moves out of the system prompt.
memory.rules-dir | memory | VERIFIED | S2 | .claude/rules/*.md | Rule files that load into context. Loading them fires the InstructionsLoaded event ([[hook.instructions-loaded]]).
memory.lazy-load-by-view | memory | VERIFIED | S6 | Lazy load by viewing a file | Subdirectory CLAUDE.md files and path-scoped rules also load when Claude views a file with cat, nl, bat, batcat, head, tail, sed -n, grep, egrep, fgrep or rg on one file, with no pipes or redirects.
memory.load-reason-session-start | memory | VERIFIED | S2 | Load reason: session_start | One of the InstructionsLoaded matcher values, recorded when a file loads at session start ([[hook.instructions-loaded]]). The meaning beyond the name is not expanded in this pass.

memory.load-reason-include | memory | VERIFIED | S2 | Load reason: include | One of the InstructionsLoaded matcher values. The meaning beyond the name is not expanded in this pass.

memory.dynamic-prompt-sections | memory | VERIFIED | S4 | Dynamic system-prompt sections | --exclude-dynamic-system-prompt-sections moves per-user context, such as the auto-memory location, out of the system prompt and into the first user message. It improves prompt-cache reuse across users. See [[flag.exclude-dynamic-system-prompt-sections]].
memory.connector-memory | memory | SESSION | S8 | Connector memory | A memory store reached through a connector is separate from Claude Code memory. The session's connector instructions describe its use.
